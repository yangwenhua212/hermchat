# UI / 文案技术规范

所有 HxSync 界面与相关 Compose 改动**必须**遵守本节。避免每次改完再靠人工要求「去掉小字」。

## 原则

1. **干净优先**：主界面、设置页、配置步进只保留**可操作的主文案**（标题、按钮、字段 label、必要状态）。  
2. **禁止说明型小字**：不要在选项卡片、列表项、输入框下方堆「备注 / hint / 灰色说明句」。  
3. **状态一句话**：成功/失败用短状态即可（如「测连成功」「测连失败」），不要附带技术细节（如 `eventId=`、长错误栈）。  
4. **长说明放文档**：协议、踩坑、接入教程写在 `docs/`，不要塞进 App UI。  
5. **错误可消失**：短暂提示（如无语音引擎）应自动消失或可点掉，不要长期占聊天顶栏。

## 允许保留

- 品牌名、Agent 显示名、按钮文字、TextField 的 `label` / 短 `placeholder`  
- 连接状态「已连接 / 未连接」  
- 确认卡标题 + 一行摘要（工具确认所必需）  
- 无障碍 `contentDescription`（不显示在视觉主文案里）

## 禁止示例

- 「电脑终端出二维码时，可直接扫码…」  
- 选项下「WebSocket 端点（模拟器访问本机用 10.0.2.2）」  
- 「需要你确认后才会操作手机。」类说教句（确认卡有标题+摘要即可）  
- 系统气泡里的调试字段  

## 实现检查清单

改 UI 或加设置项时自问：

- [ ] 删掉该行灰字后，用户仍知道点哪里吗？能则删。  
- [ ] 是否把教程写进了 `docs/` 而不是 Screen？  
- [ ] 新增枚举选项是否只有 `label`、没有附带 `hint` 展示？
